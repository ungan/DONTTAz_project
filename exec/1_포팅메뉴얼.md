# 빌드 및 배포 환경 포팅 매뉴얼 (Porting Manual)

본 문서는 Donttaz(돈땃쥐) 프로젝트를 Gitlab에서 클론(Clone)한 이후, 빌드 및 배포 환경을 구축하고 프로젝트를 실행하기 위한 가이드입니다.

---

## 1. 기술 스택 및 버전 정보 (JVM, 웹서버, WAS, DB 등)

### Backend (Server)
- **Language**: Java 17
- **Framework**: Spring Boot 3.5.11 (Gradle)
- **DB**: MySQL 8.0 (Docker-compose)
- **In-Memory Cache**: Redis (Alpine)
- **Message Broker**: RabbitMQ 3-management-alpine
- **Monitoring**: Prometheus (latest), Grafana (latest)
- **Web Server / Proxy**: Nginx (latest)
- **IDE**: IntelliJ IDEA 2024.x 등 권장

### Frontend (Application)
- **Language**: TypeScript
- **Framework**: React Native / Expo
- **Node.js**: v24.12.0 (LTS)
- **State Management**: Zustand
- **IDE**: Visual Studio Code 권장

## 3. 배포 시 특이사항

본 프로젝트는 Jenkins 파이프라인(`Jenkinsfile`)을 통해 **Zero-Downtime(무중단 Blue-Green) 배포**를 수행합니다.

1. **Blue-Green 스크립트 실행:** 
   - `donttaz-BE/scripts/deploy.sh` 스크립트를 통해 신규 릴리즈 앱 실행 (포트 교차 변경).
   - Nginx의 리버스 프록시 포트(`default.conf`의 `proxy_pass`)가 자동으로 Health Check 후 성공한 쪽으로 스위칭됩니다.
2. **보안 조치:** 
   - 배포 및 빌드가 끝난 후 서버 내에 평문으로 남은 `.env` 파일과 `firebase-service-account.json`은 젠킨스 `post` 스크립트를 통해 즉시 삭제 조치됩니다. (보안 누출 주의)
3. **프론트 배포:** 
   - 현재 프론트엔드는 Expo 빌드를 통해 `apk` (Android) 혹은 `ipa` (iOS) 형태로 결과물을 도출합니다.
   - 로컬 테스트 시 `npm start` 후 Expo Go 앱을 통해 테스트 가능.

## 4. DB 접속 정보 및 주요 사용 계정

Docker Compose 망 내 (`donttaz-net`) 혹은 로컬 포트포워딩 환경의 주요 인프라 계정입니다. 해당 설정값은 `docker-compose.yml`에도 기재되어 있습니다.

| 인프라명 | 연결 주소 (Host:Port) | 사용자명 (User) | 비밀번호 (Password) | 용도 / 특징 |
|---|---|---|---|---|
| **MySQL 8.0** | `127.0.0.1:3333` | `donttaz_user` | `u1s2e3r4` | 프로젝트 메인 애플리케이션 RDBMS |
| **MySQL (Root)** | `127.0.0.1:3333` | `root` | `a1d2m3i4n5` | DB 관리 및 덤프 백업용 계정 (실망 배포 시 패스워드 교체 필수) |
| **RabbitMQ** | `127.0.0.1:15672` (Admin UI) | `admin` | `a1d2m3i4n5` | 비동기 메시지(Webhook 등) 큐 모니터링 관리자 |
| **Grafana** | `127.0.0.1:3000` | `admin` | `a1d2m3i4n5` (초기, `GF_SECURITY_ADMIN_PASSWORD` 환경 변수) | 애플리케이션 성능/메트릭 시각화 정보 |
