# AI 서비스 DB 연동 요구사항

---

## 1. AI 서버에 보내기 위해 DB에서 꺼내야 하는 데이터

### 플랜 생성 (`POST /plans/generate`)

| 데이터 | 기간 | 필요 필드 |
|--------|------|-----------|
| 카드 거래 내역 | 최근 2~3개월 | 거래일, 금액, 가맹점명, 카테고리, 메모 |
| 계좌 거래 내역 | 최근 2~3개월 | 거래일, 금액, 입출금 구분, 적요(memo), 거래처명 |
| 현재 잔액 | 실시간 | - |
| 월급일 | - | 1~31 사이 정수 |
| 대상 년월 | - | `YYYY-MM` 형식 |

### 리포트 생성 (`POST /reports/generate`)

| 데이터 | 기간 | 필요 필드 |
|--------|------|-----------|
| 카드 거래 내역 | 해당 월 | 거래일, 금액, 가맹점명, 카테고리, 메모 |
| 계좌 거래 내역 | 해당 월 | 거래일, 금액, 입출금 구분, 적요, 거래처명 |
| 플랜 정보 | 해당 월 | 아래 **저장해야 하는 플랜 데이터** 참고 |

### 번다운 차트 (`POST /burndown/calculate`)

| 데이터 | 기간 | 필요 필드 |
|--------|------|-----------|
| 카드 거래 내역 | 최근 1~2개월 | 거래일, 금액, 가맹점명, 카테고리 |
| 현재 잔액 | 실시간 | - |
| 플랜 정보 | 해당 월 (선택) | totalBudget, sealedAmount, paydayDay |

## 2. AI 응답값 중 DB에 저장해야 하는 데이터

### 플랜 테이블

| 필드명 | 타입 | 설명 |
|--------|------|------|
| `totalBudget` | int | 사용 가능 예산 (잔액 - 봉인금액) |
| `sealedAmount` | int | 봉인금액 (월급일까지 건드리지 말아야 할 금액) |
| `surplusAmount` | int | 잉여금 (소득 - 고정지출 - 예산 - 봉인금액) |
| `riskScore` | float (0.0~1.0) | 소비 위험도 |
| `budgetStrategy` | string | `safe` / `balanced` / `tight` |
| `spendingPersona` | string (nullable) | 소비 페르소나 (예: `식도락형`, `쇼핑족`) |
| `paydayDay` | int | 월급일 |

### 카테고리 플랜 테이블 (플랜에 종속, 복수 행)

| 필드명 | 타입 | 설명 |
|--------|------|------|
| `categoryName` | string | 카테고리명 (`식비`, `쇼핑`, `교통` 등) |
| `allocatedAmount` | int | 배정 예산 금액 |
| `aiComment` | string | AI가 생성한 해당 카테고리 한 줄 조언 |

### 개인화 추천 테이블 (플랜에 종속, 3~4개 행)

| 필드명 | 타입 | 설명 |
|--------|------|------|
| `type` | string | `warning` / `action` / `habit_change` / `saving_tip` / `positive` |
| `categoryName` | string (nullable) | 관련 카테고리 (없으면 null) |
| `message` | string | 추천 메시지 문장 |

### 리포트 테이블

| 필드명 | 타입 | 설명 |
|--------|------|------|
| `achievementRate` | float | 예산 달성률 (%) |
| `aiOverallFeedback` | string | 전체 종합 피드백 문장 |

### 리포트 카테고리 테이블 (리포트에 종속, 복수 행)

| 필드명 | 타입 | 설명 |
|--------|------|------|
| `categoryName` | string | 카테고리명 |
| `allocatedAmount` | int | 예산 금액 |
| `spentAmount` | int | 실제 지출 금액 |
| `categoryRate` | float | 전체 지출 중 비중 (%) |
| `feedback` | string | `계획 범위 내 소비입니다.` 등 |

## 3. 거래 내역 테이블에 추가로 필요한 필드

카테고리 분류 결과를 저장하기 위해 거래 테이블에 아래 두 필드가 필요합니다.

| 필드명 | 타입 | 설명 |
|--------|------|------|
| `category` | string | AI가 분류한 카테고리 (사용자 수정 가능) |
| `isModified` | boolean | 사용자가 직접 카테고리를 수정했는지 여부 |

> **중요**: `isModified = true`인 거래는 AI 재요청 시 카테고리를 덮어쓰지 않아야 합니다.
> Spring에서 AI 서버에 보낼 때 이미 수정된 카테고리를 그대로 전달하면 AI가 자동으로 유지합니다.

---

## 4. 저장하지 않아도 되는 데이터

| 데이터 | 이유 |
|--------|------|
| 번다운 차트 (`chartData`, `zeroDate`, `daysToZero`) | 실시간 계산값, 요청마다 새로 계산 |
| `riskBuffer`, `rollingStd` 등 중간 계산값 | 내부 계산용, 사용자에게 노출 불필요 |

---

## 5. 카테고리 종류 (고정값)

AI 서버가 사용하는 카테고리는 아래 10가지로 고정입니다.

```
식비 / 쇼핑 / 교통 / 생활 / 여가 / 의료/건강 / 교육 / 금융/보험 / 경조사/선물 / 기타
```

DB 카테고리 컬럼은 이 값들 중 하나를 저장합니다.

## 6. 날짜/금액 형식

| 항목 | 형식 | 예시 |
|------|------|------|
| 거래일 | `YYYY-MM-DD` | `2025-03-15` |
| 년월 | `YYYY-MM` | `2025-03` |
| 금액 | 원(₩) 단위 정수 | `35000` |
| 비율 | float | `0.85` (85%) |
